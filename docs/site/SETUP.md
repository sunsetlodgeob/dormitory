# Google 側の設定手順（幹事向け）

OB会サイトの「年表」「名簿」「部屋割り」と、投稿フォームを動かすための設定です。上から順に進めてください。全部で 1 時間くらいです。

```
寮生 ─ サイトのトップページの投稿フォーム ─▶ Apps Script ─ Gemini（AI）で整理
                                                 │ そのまま「掲載」ありで入る（確認なし）
                                                 ▼
                                  スプレッドシート（鍵付き）
                                  シート「年表」「名簿」「部屋割り」（原文はシート「投稿」）
                                                 │ ページを開くたびに読む（遅くても 5 分で反映）
                                                 ▼
                                  OB会サイト（GitHub Pages）
                                  ・名簿・部屋割り … 誰でも見られる
                                  ・年表 ………… Google でログインした、見る権限のある人だけ
```

用意するもの：パソコン（スマホでは難しい）、OB会の Google アカウント、GitHub の `sunsetlodgeob` アカウント。

---

## 1. OB会の Google アカウントを作る

1. https://accounts.google.com/signup を開き、OB会用のアカウント（Gmail）を作ります。
2. パスワードは幹事のあいだで安全に引きつぎます。2 段階認証をオンにしておきます。

以下は、すべてこのアカウントでログインして進めます。

## 2. スプレッドシートを作る

1. https://sheets.new を開くと、新しいスプレッドシートができます。
2. 左上の名前を「夕照寮OB会 データ（鍵付き）」などに変えます。
3. 右上の「共有」は **「制限付き」のまま** にします。「リンクを知っている全員」には、絶対にしないでください。

## 3. Apps Script にコードを貼る

1. スプレッドシートのメニュー「拡張機能」→「Apps Script」を開きます。
2. 左上の「無題のプロジェクト」を「夕照寮OB会」に変えます。
3. 「コード.gs」の中身を全部消して、このリポジトリの [`gas/Code.gs`](../../gas/Code.gs) の中身を全部貼ります。
4. 設定ファイルを出します：左の歯車「プロジェクトの設定」→「「appsscript.json」マニフェスト ファイルをエディタで表示する」にチェック。
5. 左の「エディタ」（`< >` のマーク）に戻ると「appsscript.json」が増えています。中身を全部消して、[`gas/appsscript.json`](../../gas/appsscript.json) の中身を貼ります。
6. 保存します（フロッピーのマーク、または Ctrl+S）。

## 4. Gemini の API キーを作る

投稿を読みやすく整えて、年表・名簿・部屋割りの形にするのに使います。

1. https://aistudio.google.com/apikey を開き、OB会のアカウントでログインします。
2. 「API キーを作成」を押し、できたキー（`AIza…` で始まる長い文字）をコピーします。プロジェクトを選ぶように言われたら、出てきたものをそのまま選びます。
3. このキーは **人に見せない・GitHub に書かない** でください。

## 5. スクリプト プロパティを入れる

1. Apps Script の左の歯車「プロジェクトの設定」→ いちばん下の「スクリプト プロパティを追加」。
2. 次のように入れて、「スクリプト プロパティを保存」を押します。

| プロパティ | 値 |
| --- | --- |
| `GEMINI_API_KEY` | 4 でコピーしたキー |
| `GEMINI_MODEL` | 入れなくてよい（いちばん新しい Flash モデル `gemini-flash-latest` を使う）。手順 12 の「困ったとき」を参照 |
| `CLIENT_ID` | 8 で作るクライアント ID（あとで入れる） |

## 6. setup を実行して、許可する

1. Apps Script の上にある関数の選択で「setup」を選び、「実行」を押します。
   **必ず OB会のアカウントで** 実行してください。ほかのアカウント（幹事の個人のアカウントなど）だと止まるようにしてあります。
2. 「承認が必要です」→「権限を確認」→ OB会のアカウントを選びます。
3. 「このアプリは Google で確認されていません」と出ます。これは **自分で作ったスクリプトなので出る画面** です。「詳細」→「夕照寮OB会（安全ではないページ）に移動」を押します。
4. 許可する項目が並びます（チェックを付ける形なら「すべて選択」）。「許可」を押します。
5. 下の「実行ログ」に「準備ができました」と出れば OK です。

できるもの：シート「年表」「名簿」「部屋割り」「メンバー」「投稿」「D-1」。1 行目に見出しが入り、「掲載」の列はチェックボックスになります。
`setup` は何度実行しても、シートが増えたり、中身が消えたりすることはありません。
同じ名前で形のちがうシート（前から作ってあった「名簿」など）は、「名簿（元）」のように名前を変えて、中身はそのまま残します。

### 前から作ってあった表を取り込む

前から作ってあった「事件簿」「名簿」「D-1選手権年表」は、サイト用のシートに写せます。

1. スプレッドシートを読み込みなおすと、上のメニューに「OB会」が出ます。まず「OB会」→「Gemini のキーを確かめる」で、「使えます」と出るのを確かめます。
2. 「OB会」→「事件簿・名簿・D-1 を取り込む」を押します（初めてのときは、6 と同じように許可します）。
3. 終わると、何件入れたかが出ます。

- 事件簿 → 年表：年月から年度（4月はじまり）と月を読みます。見出し・本文・タグは Gemini が整えます（手順 5 の `GEMINI_API_KEY` が要ります）。「［確認］…」の行はサイトに出さず、メモに入れます。
- 名簿（元）→ 名簿：「度」を入学年度として、「、」「・」で区切った名前を 1 人 1 行にします。年度が空の行は、上の行の年度です。「それ以前」の人は、名簿の最初に「それ以前」のまとまりで出ます。
- D-1選手権年表 → D-1：出場メンバーのうち、赤い字の人を優勝、太字の人を準優勝にします。「主催者・補足」は「レフェリー：」「黒子：」などで分けます。
- どれも「掲載」ありで入ります。もとの表は変えません。
- 何度押しても、取り込みずみの行はとばします（もとの表に足した行だけ入ります）。件数が多くて時間切れになったり、Gemini が混んでいたり使えなかったりしたら、事件簿はそこで止まります（原文のままは入れません）。少しおいて（キーを直して）もう一度押すと、続きから入ります。
- これからは、サイト用の「年表」「名簿」「D-1」のシートを直接直してください。

ほかのデータ（部屋割りなど）は、列の形を [`docs/site/DATA.md`](DATA.md) のとおりにして、直接貼ってかまいません。サイトに出したい行の「掲載」にチェックを入れます（まとめて選んでスペースキーで入ります）。

## 7. ウェブアプリとして公開する

サイトがデータを読みに来る窓口です。

1. Apps Script の右上「デプロイ」→「新しいデプロイ」。
2. 「種類の選択」の歯車 →「ウェブアプリ」。
3. 説明：「OB会サイト用」。次のユーザーとして実行：**自分**。アクセスできるユーザー：**全員**。
4. 「デプロイ」を押します（「アクセスを承認」と出たら、6 と同じように許可します）。出てきた「ウェブアプリ」の URL（`https://script.google.com/macros/s/…/exec`）をコピーします。
5. 確かめる：その URL の後ろに `?type=public` を付けてブラウザで開き、`{"ok":true, … "members":[…], "rooms":[…]}` のように出れば OK です（掲載にチェックした名簿・部屋割りが入っています）。

「全員」にしても、サイトに返すのは「掲載」にチェックした行の決まった項目だけです。シートそのものは見えません。
投稿フォームの受け口もこの URL です（だれでも送れますが、いたずらよけの問い・同じ内容の 2 回目をはじく・1 時間に 30 件まで、の仕組みがあります）。

## 8. 年表のログイン用のクライアント ID を作る

年表を開いた人が「Google でログイン」できるようにします。

1. https://console.cloud.google.com/ を OB会のアカウントで開きます（初めてなら利用規約に同意）。
2. 上の「プロジェクトを選択」→「新しいプロジェクト」→ 名前「yusho-ob」→「作成」。できたプロジェクトを選びます。
3. 左のメニューから「Google Auth Platform」（古い画面では「API とサービス」→「OAuth 同意画面」）を開き、「開始」。
   - アプリ名：夕照寮OB会 ／ ユーザー サポートメール：OB会のアドレス
   - 対象：**外部**
   - 連絡先：OB会のアドレス → ポリシーに同意 →「作成」
   - ロゴは入れない（入れると審査が要ります）。権限（スコープ）も追加しない。ログインに使うのは基本の項目（メールアドレス・名前）だけなので、審査は要りません。
4. 「対象」→ 公開ステータスの「アプリを公開」→ 確認（**本番環境** にする）。「テスト中」のままだと、テストユーザーに登録した人しかログインできません。
5. 「クライアント」→「クライアントを作成」。
   - アプリケーションの種類：**ウェブ アプリケーション** ／ 名前：OB会サイト
   - 承認済みの JavaScript 生成元：「URI を追加」で次の 3 つ
     - `https://sunsetlodgeob.github.io`
     - `http://localhost` と `http://localhost:8000`（手元で確かめる用。2 つとも要ります）
   - 承認済みのリダイレクト URI：何も入れない
   - 「作成」
6. 出てきた「クライアント ID」（`…apps.googleusercontent.com`）をコピーします。
7. Apps Script の「プロジェクトの設定」→ スクリプト プロパティ `CLIENT_ID` に貼って保存します（デプロイのやりなおしは要りません）。

## 9. サイトの設定ファイルに書く

1. GitHub に `sunsetlodgeob` でログインし、https://github.com/sunsetlodgeob/dormitory の `js/site/config.js` を開きます。
2. 右上の鉛筆のマーク（Edit this file）を押し、`''` の間に値を入れます。

| 項目 | 入れるもの |
| --- | --- |
| `GAS_URL` | 7 のウェブアプリの URL（`…/exec`） |
| `GOOGLE_CLIENT_ID` | 8 のクライアント ID |
| `CONTACT_EMAIL` | OB会の連絡先（個人のアドレスではなく、OB会のアドレス） |

3. 「Commit changes…」→「Commit changes」で保存します。

`GAS_URL` を入れると、トップページの投稿フォームが使えるようになります（空のあいだは「準備中」と出ます）。

ここに書く値はサイトを見た人にも見えますが、困らないものだけです。**Gemini の API キーはここに書かないでください。**

## 10. GitHub Pages を有効にする

1. https://github.com/sunsetlodgeob/dormitory の「Settings」→ 左の「Pages」。
2. Build and deployment の Source：「Deploy from a branch」。Branch：「main」、フォルダ：「/ (root)」→「Save」。
3. 数分で https://sunsetlodgeob.github.io/dormitory/ が開けるようになります。

## 11. ふだんの運用

### 投稿が来たら
- トップページの投稿フォームから送られた内容は、Gemini が整えて、シート「年表」「名簿」「部屋割り」に **「掲載」ありで** そのまま入ります（幹事の確認はありません）。サイトにはすぐ出ます。
- 送られた原文と、どこに何を入れたかは、シート「投稿」に 1 件 1 行で残ります。年表などの行の「元の回答」を押すと、その投稿の行に飛べます。
- ときどきシート「投稿」を見て、おかしなものは手で直します。消したいときは、その行の「掲載」のチェックを外します（行を消してもかまいません）。
- 名簿の訂正（入学年度・卒業年度・名前の漢字）は、同じ名前の行を書きかえます。前の値はその行の「メモ」に残ります。「名簿から外して」という投稿は、名簿と部屋割りの「掲載」を外します。
- 部屋割りは、年度・部屋・名前の組がもうあれば足しません。「まちがいなので消して」という投稿は、その組の「掲載」を外します。
- メモに「Gemini失敗：手で整理してください」とある行は、AI で整えられなかったものです。原文のまま入っているので、手で直してください。
- メモに「名簿掲載NG」と書いた行は、「掲載」にチェックがあってもサイトに出ません（本人が載せたくないと言ったときなどに、幹事が手で書きます）。
- 入学年度が空の名簿の行、年度か部屋番号がおかしい部屋割りの行は、サイトに出ません。
- 「卒業年度」は、卒業した年度です（2007年3月に卒業したなら 2006）。名簿には「2006年度卒」と出ます。
- 写真は投稿フォームでは受けつけていません。写真館（下の「写真館」）で管理します。

### 写真館
写真は、OB会の Google ドライブのフォルダに置いたまま、サイトの写真館で見せます（見られるのは、年表と同じく承認された人だけ）。

1. スプレッドシートのメニュー「OB会」→「写真を取り込む（重複と年度の仕分け）」を押します。初めてのときは、写真のフォルダの URL をきかれるので、ドライブでそのフォルダを開いたときの URL を貼ります（下のフォルダの中も全部読みます）。
2. シート「写真」に 1 枚 1 行で入ります。写真そのものは動かしません。
   - **年度**：写真の中の撮影日から（4月はじまり）。撮影日がなければ、フォルダ名・ファイル名の年（「2005新歓」など）から。どちらもなければ空（サイトでは「年度不明」）。**「年度」の欄を書きかえると、その年度に移ります。**
   - **重複**：同じファイルのコピーと、同じ撮影時刻（秒まで）で縦横の比が同じ写真（縮めた版など）は、いちばん大きい 1 枚だけを残し、ほかは「掲載」のチェックなしで入ります（メモに「重複（…）」）。まちがいなら「掲載」にチェックを入れれば出ます。
   - 見せたくない写真は、「掲載」のチェックを外します。
3. フォルダに写真を足したら、もう一度「写真を取り込む」を押します。新しい写真だけが入ります。別のフォルダにするときは「写真のフォルダを変える」。
4. **ダウンロード**：シート「設定」の「写真のダウンロード」にチェックを入れると、写真館で元の写真をダウンロードできます。外すとできません（画面の写真を保存されるのは、完全には防げません）。

### 年表を見られる人を決める
年表を見られるのは、次のどれかの人です（Google アカウントのメールアドレスで判断します）。

- **シート「申請」で「承認」にチェックした人** ← ふつうはこれ
  - 年表のページでログインして、まだ権限のない人には「見る権限を申請する」の欄が出ます（お名前・入学年度・ひとこと）。
  - 申請が来ると、シート「申請」に 1 人 1 行で入り、OB会のアカウントにメールが届きます（スクリプト プロパティ `NOTIFY_EMAIL` にアドレスを入れると、そちらに届きます）。
  - 見せてよい人なら、その行の「承認」にチェックを入れます。数分で見られるようになります。チェックを外すと、また見られなくなります。
- シート「メンバー」の「メールアドレス」の列に書いた人（申請なしで、先に入れておきたいとき）
- このスプレッドシートを共有した人（オーナー・編集者・閲覧者）

スプレッドシートを共有すると、掲載していない投稿やメモ・申請まで全部見えてしまいます。共有は幹事だけにして、寮生は「申請」か「メンバー」で見られるようにしてください。

### コードを直したとき
`Code.gs` を貼りなおしたら、デプロイもやりなおします。

1. 「デプロイ」→「デプロイを管理」→ 鉛筆のマーク。
2. バージョン：「新バージョン」→「デプロイ」。

URL は変わらないので、`config.js` を書きかえる必要はありません。`appsscript.json` も貼りなおしたときは、関数「setup」をもう一度実行して、許可しなおしてから、デプロイをやりなおしてください（使う権限が変わることがあるため。許可しないままだと、サイトからの申請や投稿が動きません）。投稿フォームの質問を変えたいときは、サイトの `index.html`・`js/home/post.js` と `Code.gs` の両方を直します（相談してください）。

## 12. 困ったとき

| こんなとき | 見るところ |
| --- | --- |
| 年表で「このアカウントには見る権限がありません」 | その人のアドレスが「メンバー」にあるか。Google にログインしているアドレスと同じか |
| 年表で「年表の準備がまだ終わっていません」 | スクリプト プロパティ `CLIENT_ID` が入っているか |
| ログインのボタンが出ない・エラーになる | 8 の「承認済みの JavaScript 生成元」と、公開ステータスが「本番環境」か |
| 投稿フォームが「準備中」のまま | `config.js` の `GAS_URL` が入っているか |
| 投稿で「うまく送れませんでした」 | Apps Script の左の「実行数」で doPost のエラーを見る。`Code.gs` を貼りなおしたあと、デプロイの「新バージョン」を忘れていないか（手順 11） |
| 投稿がシートに増えない | シート「投稿」に原文が入っているか。入っていれば「結果」の列を見る。入っていなければ、上の「実行数」を見る |
| setup で「オーナー（OB会のアカウント）でログインして実行してください」 | 右上のアカウントを OB会のアカウントに切りかえてから、もう一度実行する |
| どの投稿も「Gemini失敗」になる | メモの「HTTP …」の数字を見る。**400・403**：`GEMINI_API_KEY` がまちがっているか、無効になっている（4 をやりなおす）。**429**：無料枠の回数の上限。時間をおけば、次の投稿からは通ります。**404**：モデルの名前が古い。`GEMINI_MODEL` を入れているなら消す（空にする）。「APIキーが未設定」：手順 5 |
| 「Gemini失敗」の行 | 原文のまま、掲載ありで入っています。年度・月・部屋は仮に読み取ったものなので、確かめて直してください |
| サイトの名簿が空のまま | `config.js` の `GAS_URL` が `/exec` で終わっているか。「掲載」にチェックしたか |

## 個人情報について（大事）

- **Gemini の無料枠** に送った文章は、Google がサービスの改善に使うことがあります（人が読むこともあります）。実名の入った事件簿を通すなら、AI Studio で支払い情報を設定して **有料枠** にするか、投稿で名前を書かない（呼び名にする）ようにお願いしてください。このスクリプトは、事件の「関わった人」と「投稿者」の欄は Gemini に送りません。事件の本文に書かれた名前と、名簿・部屋割りの名前（どちらも誰でも見られるページに出るもの）は送ります。
- **写真館** の写真は、OB会のドライブに置いたままにし、承認された人にだけサイトで見せます。ドライブのフォルダは「共有」しないでください（共有すると、承認していない人も見られます）。
- スプレッドシートは「制限付き」のまま。API キーは GitHub やメールに書かない。
- 投稿は確認なしで「掲載」ありになります。名簿・部屋割りは誰でも見られるので、本人以外の名前が入ったり、載せたくない人が載ったりしたら、すぐ「掲載」のチェックを外してください。
- サイトに出るのは、「掲載」にチェックした行の、決まった項目（名簿は名前と年度、部屋割りは年度・部屋・名前、年表は年度・月・見出し・本文・タグ）だけです。
